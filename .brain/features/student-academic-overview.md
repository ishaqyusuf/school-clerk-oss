# Student academic overview and history

## Class-change client and options — 2026-09-08, implemented but untested

ADR-0056 adds a dedicated selection-derived destination read with fresh same-school/student/parent/session/open-term validation. It returns minimal classroom IDs/labels rather than broad classroom statistics. One hook now owns overview and bulk options/submission, binds displayed identity/selection/target, masks unavailable/stale reads, blocks overlapping or offline-queued moves, guards local callbacks and invalidates owned records plus directory/classroom/report/attendance/search queries. Canonical deletion and term removal invalidate destination options too.

Both views reset destinations on context changes and present loading/error/empty/retry/removed-target and explicit moved/repeat results. Picker items, confirmation/refresh controls and mobile bulk trigger have 44px provisions and accessible labels; overview uses native confirmation and bulk errors stay in the dialog. Existing history/default-effect limitations remain unchanged. This supersedes the prior pending shared-client work below; admission/fee reconciliation, class-bound historical reporting, other domain/lifecycle work and all browser/mobile verification remain open.

## Class changes — 2026-09-08, backend written and untested

ADR-0055 replaces single/bulk class writers with one live-authorized, whole-batch Serializable service. Validate school/session/term/canonical/parent ancestry and duplicate identities/names, reject closed terms, lock canonical students and atomically update changed term placements plus parent session defaults. Other term placements and financial/assessment/attendance histories remain unchanged. Matching repeats are explicit and do not independently reset later defaults; original subject/register links are not transferred to the destination.

Both current clients disable retry/offline queueing; directory bulk confirmation retains errors/selection and checks bounds, while overview shows inline recovery/history guidance. Full scoped client callbacks, precise invalidations, fresh target-option reads and mobile recovery conformance remain required implementation. Class-specific history/report transfer behavior and all tests/browser/mobile QA remain open; this is not whole-feature completion.

## Term-detail preview — 2026-09-08, implemented but untested

ADR-0054 replaces the remaining inline term-detail read with a live-authorized API transaction and DB-owned target/section projections. Admin/Registrar + Students/Academics is mandatory; assessment/attendance modules and the narrower Finance/Admin intersection independently govern sections. Restricted/inconsistent sections return nullable withheld counts, not false zeros. Real charge/allocation previews replace empty finance placeholders, with deterministic 50-row limits and exact qualifying counts; allocations are applied amounts, not full receipts or a balance statement.

Promotion's confirmation is extracted into a dedicated component/query hook. School/user/login/role/module-revision keys, returned-scope agreement and loading/refetch/error/paused masking prevent known stale-scope display. Explicit retry refreshes module state first; closed terms remain readable but cannot be removed. Stacked sections, wrapping content, scroll limits and 44px actions are written, not mobile-tested. No stored records change. Broader report/directory reads, class-change/lifecycle services and all deferred verification remain open.

## Term removal boundary — 2026-09-08, implemented but untested

Single and bulk enrollment removal share one live-authorized Serializable DB service (ADR-0052). All requested forms must have consistent school/student/session ownership; active closed-term forms reject the whole batch. Only selected term forms are archived, retaining the canonical student, session-level placement and financial/assessment history without cancelling balances. Responses separate newly removed and already-removed counts and identify owned students for future precise invalidation.

ADR-0053 adds shared scope-bound client orchestration across all seven mutation instances in overview, directory, promotion, progression and report filters. The hook supplies displayed identity, prevents overlap/retry/offline queues, fences callbacks/errors to the originating mounted view and invalidates owned student/term plus related list/report queries. Directory/progression reject unavailable selections rather than submitting a subset. Confirmations retain errors, explain archival/unchanged balances and use viewport-capped/wrapping 44px controls; promotion summaries stack on narrow screens and repeat toasts distinguish already-archived rows. Report filters now use the provider hook. All tests and mobile/browser QA remain deferred. ADR-0054 adds the separate term-detail read boundary; broader report/directory/class-change boundaries still require implementation work.

Status: guarded read implementation written, untested (2026-09-08). [ADR-0045](../decisions/ADR-0045-student-academic-read-boundary.md).

## Read contract

- ADR-0048 replaces inline fee-preview queries with a bounded schema, live-authorized API transaction and DB-owned projection. Missing/foreign term/classroom now errors instead of returning no fees; closed terms reject enrollment preview. Admission/gender remain simulated selectors for student creation. The fee-list DTO is unchanged; optional viewScope is checked against current school/user/login session.
- One scoped preview hook serves overview enrollment and student creation, including its footer. It withholds stale/loading/error/paused/placeholder values; failed preview never appears as no fees, payment controls/totals are withheld while unavailable, and submit for enrollment/payment awaits ready data. Explicit retry and mobile-stacked payment controls are implemented. Draft selections are retained until current data can reconcile them. No runtime or mobile behavior is verified.
- ADR-0047 adds `capabilities.enroll` to overview: the read still requires Students/Academics, while enrollment additionally requires Finance because it applies fees. The enrollment RPC now uses a guarded Serializable DB transaction and returns `enrolled`/`already-enrolled` with scoped form IDs. A matching repeat does not reapply fees. Classroom is required; explicit session forms and every target relationship are validated; conflicting/malformed history is rejected. See ADR-0047 for limits against other writers.
- Overview and find-and-enroll show pending/error states and disable automatic mutation retries. Overview fee preview distinguishes loading, error, missing class, no matches, required fees and unselected optional fees; enrollment is unavailable until the preview is ready. This is not a price lock or substitute for the current server-side checks. Responsive controls are implemented, untested.
- ADR-0046 adds `enrollmentState`: enrolled requires exactly one current and fully valid form; not-enrolled requires no current term reference and no unmapped history; otherwise unavailable. Scalar reference integrity checks never expose foreign IDs/content. Unavailable history displays “Needs review”, suppresses enrollment/move/delete-term controls and never inherits a missing-term placement. No stored record is changed.
- Optional bounded `viewScope` binds school/user/login session to live server context. Overview responses include matching `scope`. A dedicated client hook plus matching server prefetch keys isolate the page, overview sheet and basic-info editor; returned scope must match visible identity. It withholds stale/refetch/error/paused/placeholder data and collects unused caches immediately. Existing student-ID invalidations match the scoped query inputs.
- Fresh mounts, manual refresh and mutation invalidation reauthorize. Automatic timer/focus/reconnect refresh is disabled to avoid silently discarding an active editor. Dedicated loading/error/retry notices and history-review notice use wrapping layout and 44px controls. Basic editor cannot save without current data and resets on scope/student changes; enrollment form resets on student/term changes and checks submitted identity. These are source-level provisions, not verified UI outcomes.
- Shared API service `student-academic-read.ts` validates 1–200 character student IDs and optional nullable term/term-sheet IDs, reloads live identity and modules, and maps data from DB-owned `student-academic-read.ts` in one RepeatableRead transaction.
- Management reads require Admin/Registrar, active stored session/account/school and both Students and Academics. This does not grant parent/teacher directory access or couple all student operations to Academics.
- `students.overview` returns `{ id, student, studentTerms }`; `academics.getStudentTermsList` returns the same term list; `students.academicsOverview` returns `{ id: null, student, termHistory, term }` with its existing student-summary keys. The academic summary is now derived from the same guarded snapshot, not a separate general-directory query.
- Student and live guardian must belong to the active school. History includes live school terms with live school sessions. Form/session/classroom/student-session ancestry must agree before placement metadata appears.
- Duplicate valid forms withhold term-form and placement links for that term. Missing-term placement may inherit only a unique same-session tuple; it never creates a term-sheet link. Ambiguous placements stay empty. An explicit absent/foreign/mismatched term or term-sheet selector returns NOT_FOUND. Default selected sheet uses the first valid enrolled term in descending end-date order, with ID tie-breaker.
- Guardian selection uses the earliest live same-school guardian relation with a deterministic ID tie-breaker. Name formatting uses current school configuration.

## Remaining work

ADR-0045 was backend-only; ADR-0046 adds responsive state/recovery controls and scoped client reads. ADR-0047 covers this specific term-enrollment transaction; ADR-0048 covers the fee-preview service/query/client boundary. Role-specific/tab-specific projections, other student mutations/create/import paths and broader finance integrity remain implementation work. No mobile/browser behavior is verified. Preserve existing records; do not interpret withheld malformed or ambiguous history as permission to recreate/delete it.

Deferred tests include forged IDs, direct callers, role/module denial, deleted/expired identity, foreign/archived relationships, session mismatch, duplicate forms, placement fallback, selector mismatch, response consumers and browser/mobile recovery flows. No tests/typechecks/builds/lint/formatters, schema actions or live requests ran.
